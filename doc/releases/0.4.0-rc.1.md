# esp_provisioning_wifi 0.4.0-rc.1

Release candidate for native Bluetooth readiness, cancellation and stale
permission-result protection. Supports Equatable 2 and 3 while keeping the
Flutter 3.24 / Dart 3.5 consumer floor and Android API 23 / iOS 13 minimums.

## Upgrade

1. Pin `esp_provisioning_wifi: 0.4.0-rc.1`, run `flutter pub get`, then rebuild
   your app. Run `pod install` in an existing iOS workspace as appropriate.
2. Existing provisioning APIs remain available. Use the public package import
   for `EspBluetooth.ensureReady()` and handle on/off/unauthorized/unavailable/
   unknown results, cancellation and timeout. Retain native permission prompts
   and settings guidance; iOS cannot enable its radio programmatically.
3. Complete readiness before starting provisioning: readiness and provisioning
   share the single-operation model. Dispose the setup BLoC on leaving the flow.
4. Qualify physical permission dialogs, radio off/on, background/foreground,
   cancellation, immediate retry, Wi-Fi scan/join, wrong proof of possession and
   your supported ESP32 firmware before production rollout.

## Artifacts and validation

The pub.dev archive is the library distribution: Flutter compiles its native
code for the consuming app. Release assets also include a debug Android example,
an unsigned iOS example and checksums. Examples are validation builds and do not
replace your own signed application.

Release CI covers Dart analysis/tests, the minimum Flutter consumer, Android
compilation/native tests/lint, Swift tests and unsigned iOS compilation. Physical
Android/iOS BLE and preserved legacy firmware qualification remain outstanding;
this candidate does not claim those checks or resolve unreproduced support cases.
